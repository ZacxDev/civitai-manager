Stop hunting for the models a workflow forgot to ship.

civitai-manager imports a ComfyUI workflow, checks it against your actual install, finds the model files you're missing, downloads them into the right folder — and starts the run when they land. You don't re-click.

The loop this replaces

Every downloaded workflow is a scavenger hunt for someone else's file layout.

Prompt outputs failed validation: ckpt_name: 'value not in list'

So you open the node, guess which checkpoint that string meant, search CivitAI, download it, work out whether it belongs in checkpoints/ or unet/, drop it in, restart, hit Run — and it fails on the next missing file. Repeat until you give up or the workflow finally goes.

What happens instead

The preflight knows what your ComfyUI actually has, so the gap is a to-do list, not a mystery.

Before submitting anything, civitai-manager diffs the graph against your live ComfyUI. Missing model files are resolved on CivitAI — with a HuggingFace fallback for the VAEs and upscalers that never had a CivitAI page — and downloaded into the correct models/ subfolder. The run is queued behind the download and starts on its own.

Saved sampler or scheduler values your build doesn't have get a dropdown of the ones it does. Prompt, seed, steps and cfg are editable in place — without touching the workflow you imported.

The honest caveat, up front: this resolves model files. It does not install custom nodes. If a workflow needs a node pack you don't have, it names the missing nodes and stops — installing them is still your job.

How it works

Three steps, one of which is waiting.

1

Import the workflow

Paste the JSON, drop in a PNG that ComfyUI generated and let it read the graph out of the metadata, scan your install for workflows already on disk, or import straight from CivitAI's workflow listings.

2

Click Run

The graph is converted to API format — expanding subgraphs, resolving Get/Set teleports, splicing bypassed nodes — then checked against your live ComfyUI for missing nodes, missing models, and options your build doesn't have.

3

Let it fetch

Pick a match, an already-installed substitute, or download-and-run. The file lands in the correct subfolder, the run starts when it completes, and the images are captured to a gallery with the parameters that made them.

Running workflows

Requires a running ComfyUI — by default the one on 127.0.0.1:8188.

Conversion that survives real graphs

Subgraph expansion, Get/Set teleport resolution, bypassed and muted node splicing, rgthree UI-only nodes dropped, converted widgets handled without shifting every value after them.

Preflight, not trial and error

Missing nodes, missing models, and incompatible enum values are reported separately — each diffed against your live ComfyUI rather than guessed.

Multi-match resolution

When several CivitAI models fit a filename you get the best match plus the alternates, so you disambiguate deliberately instead of hoping.

HuggingFace fallback

For files CivitAI never hosted. Auto-download is deliberately narrow — curated map or recognised org, ungated, SHA256 known. Everything else becomes a link with the reason stated.

Editable run parameters

Prompt, seed, steps, cfg, sampler, scheduler, denoise, dimensions and batch size — traced back to the node that actually holds each value. The stored workflow is never modified.

Durable output gallery

Every successful local run is captured with the parameters that produced it, and re-run reconstructs them. Disk-capped at 20 GiB by default, oldest evicted first.

And it manages the library underneath

The other half of the tool, for when models/ has become a landfill. All of this works with ComfyUI closed.

Subscribe to models and creators

A poller diffs each subscription's version list and queues genuinely new versions. Downloads are verified against the API's SHA256 where one is published. Subscribing seeds the back-catalog without downloading it, so you never retro-pull 300 GB.

Scan what you already have

Hashes your model directories — with an mtime/size cache so re-scans skip unchanged multi-GB files — matches the whole set against CivitAI in one batch lookup, and flags duplicates, superseded versions and broken files.

Nothing is ever hard-deleted

Acting on a flag moves the file to a trash directory with an undo manifest. The mover refuses to leave zero copies of a duplicate set, refuses unmatched files, and refuses the newest version.

Limitations

Worth reading before you decide it's broken. This is v0.1.x software.

  • Custom nodes are not installed for you. Only model files are resolved and downloaded. A workflow needing an uninstalled node pack won't run until you install it yourself.
  • A graph the converter can't fully understand blocks the run rather than submitting something partially broken.
  • Parameters inside subgraphs aren't editable, and the parameters panel only appears for UI-format workflows.
  • CivitAI cloud runs don't resolve custom node packs — model resources map to AIR URNs automatically, node packs you supply yourself.
  • Cloud run results aren't captured into the output gallery. Only local runs are.
  • The ComfyUI helper extension needs one restart to activate, and another to fully remove.
  • Preflight checks against its own file index, not ComfyUI's models directory — a file in your library but not where ComfyUI looks will pass, then fail inside ComfyUI.
  • The web UI has no login. Loopback by default; binding a LAN address exposes an unauthenticated UI and your output gallery.
  • NSFW previews are blurred, not withheld. Blur is a browser-side filter — the bytes are still sent.
  • Two things phone home by default, both disclosed and switchable: scan matching sends file hashes to CivitAI; the fallback sends a missing filename to HuggingFace.
  • The schema still moves between releases. Migrations run automatically, but treat it as unstable.
  • Interrupted downloads are re-fetched whole, not resumed, and search returns the first page only.

Install

One binary. No runtime, no database server, no container.

Install script

# detects OS/arch, verifies against checksums.txt
curl -fsSL https://zacxdev.github.io/civitai-manager/install.sh | sh

Installs to /usr/local when that's already writable, otherwise ~/.local — no surprise sudo. Read it first: install.sh.

Nix

# run it without installing anything
nix run github:ZacxDev/civitai-manager -- --version
nix profile install github:ZacxDev/civitai-manager

Homebrew, packages, Go

brew install --cask ZacxDev/tap/civitai-manager
sudo dpkg -i civitai-manager_0.1.76_linux_amd64.deb
sudo rpm  -i civitai-manager_0.1.76_linux_amd64.rpm
go install github.com/ZacxDev/civitai-manager@latest

The script, packages, cask and attestations ship from v0.1.76; the cask reaches the tap with that release. Every option, plus gh attestation verify, is in the install guide.

Then run it

# point it at your ComfyUI models folder so it
# can install missing files where ComfyUI looks
civitai-manager serve --comfy-model-path ~/ComfyUI/models

# → open http://localhost:8787

Add a CivitAI API token before downloading much — browsing works anonymously, but most file downloads need auth. If you already use the official civitai CLI, your existing token is picked up automatically.

Released for linux, macOS and Windows on amd64 and arm64, with a checksums.txt. SQLite is the pure-Go driver, so every build is CGO_ENABLED=0 — no C toolchain anywhere.

Running workflows needs ComfyUI running. Subscriptions, downloads, the library scanner, workflow import and browsing all work with it closed — see the full breakdown.
